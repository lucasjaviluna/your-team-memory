El sistema

¿Qué es team-memory?

El conocimiento generado en sesiones de IA — decisiones, bugs resueltos, convenciones, anti-patrones — se pierde cuando se cierra la terminal. team-memory lo captura, lo estructura y lo hace disponible para cualquier dev, en cualquier sesión futura, sobre cualquier proyecto del equipo.

🔐 100% on-premise

Embeddings y generación con Ollama local. Nada del conocimiento del equipo sale de la red interna.

🌐 Instalación global

Un comando configura el MCP en Claude Code, Copilot, VS Code, Cursor y OpenCode. Sin tocar configs por proyecto.

🖥️ TUI interactiva

Terminal UI para buscar, navegar, editar y compactar entradas desde la línea de comandos.

Transporte

Modos de conexión

💻 stdio — servidor local

El MCP corre como subproceso del cliente IA. Sin red, sin puertos expuestos. Configurado con MCP_TRANSPORT=stdio en el .env.

{ "command": "node",
  "args":    ["...dist/index.js"],
  "env":     { "MCP_TRANSPORT": "stdio" } }
⚠️
Expone credenciales al cliente. Solo para administradores del servidor.

🌐 Streamable HTTP — producción

Servidor compartido del equipo. Endpoint único /mcp, modo stateless. Las credenciales viven solo en el servidor.

# .env
MCP_TRANSPORT=http
MCP_PORT=3100         # puerto configurable
{ "url": "http://10.0.0.5:3100/mcp" }
ℹ️
Streamable HTTP es el transporte vigente del protocolo MCP (SSE quedó deprecado en marzo 2025). La TUI también usa este endpoint — no necesita acceso directo a la DB.
Config por repositorio

.team-memory.json

Archivo commiteado en el root de cada repo. Define el slug del proyecto y la resolución de área. Todos los devs que clonan el repo lo heredan automáticamente.

Repo de una sola capa

{
  "project_slug": "admin-dashboard",
  "default_area": "frontend"
}

Repo fullstack

{
  "project_slug": "ecommerce-platform",
  "default_area": "general",
  "area_map": {
    "src/frontend/": "frontend",
    "src/backend/":  "backend",
    "docker/":       "infra",
    ".github/":      "infra"
  }
}
✅
El archivo no contiene credenciales — es seguro commitearlo. Define qué proyecto es y cómo mapear directorios a áreas.
Patch V3.2

Resolución de project_slug

El agente busca .team-memory.json subiendo desde el directorio actual hasta el root del repo (.git). El primero que encuentre gana — útil en monorepos.

A
Existe y tiene project_slug
Usar directamente. Informar: [team-memory] Proyecto: ecommerce-frontend (.team-memory.json)
B
Existe pero sin project_slug
Flujo interactivo → actualizar el campo sin tocar otros campos del archivo.
C
No existe
Flujo interactivo → crear el archivo con { "project_slug": "..." }. Recordar commitearlo.

Flujo interactivo (B y C)

  2) frontend            (package.json)
  3) ecommerce           (carpeta raíz)
  4) Otro — indicame cuál
Patch V3.3

Resolución de area — cascada de 4 niveles

Sistemática y consistente entre sesiones y devs. El primero que aplica gana.

1
area_map en .team-memory.json
Prefijo de ruta más largo que coincide con el archivo activo. src/frontend/button.ts + mapa "src/frontend/":"frontend" → frontend.
2
default_area en .team-memory.json
Área default del repo. Para repos de una sola capa, con esto alcanza.
3
Inferencia heurística
Imports (@angular/, express, prisma), extensiones (.component.ts, .scss), archivos (Dockerfile, docker-compose.yml).
4
Preguntar al dev
Solo cuando los tres niveles anteriores fallan. Con tip de cómo evitarlo la próxima vez.
💡
Cross-area: usar area: 'general' con tags específicos (['frontend','backend']). El área general es exactamente para conocimiento que aplica a más de una capa.
Onboarding

Instalador CLI — global, una vez

Un comando configura el MCP en todas las herramientas de IA detectadas y registra el protocolo de uso. No requiere clonar el repo del servidor.

npx github:tu-org/team-memory install

Resolución de URL

1
--url explícito
Siempre tiene prioridad. Útil para staging u otro servidor.
2
team-memory.config.json → defaultUrl
URL por defecto del repo de la organización. Configurada una vez por el tech lead.
3
Variable de entorno TEAM_MEMORY_URL
Para distribución vía npm o scripts de onboarding automatizados.

Patch V4.1

Instalación de la TUI

La TUI requiere tener el repo clonado — a diferencia del instalador del MCP que no necesita clonar nada. El subcomando install-tui automatiza todo el proceso.

# Desde la raíz del repo clonado
git clone https://github.com/tu-org/team-memory
cd team-memory
npm run install-tui

# Equivalente — mismo efecto
node packages/installer/cli.mjs install-tui

Qué hace install-tui

1

Verificar repo

Busca packages/tui/package.json. Si no existe, muestra instrucciones para clonar.

2

npm install

Instala las dependencias de la TUI en packages/tui/node_modules/.

3

Compilar TypeScript

Corre npx tsc en el paquete de la TUI y genera packages/tui/dist/.

4

Crear comando global

Escribe ~/.local/bin/memory-tui con permisos 755. Avisa si el directorio no está en el PATH.

V4 — Terminal UI Phase 1

memory-tui

Interfaz de terminal para gestionar la memoria del equipo sin pasar por un agente de IA. Comunicación via HTTP al mismo servidor MCP — funciona con el servidor local o el de producción.

Stack

  • TypeScript + React + Ink 5
  • ink-select-input@6 + ink-text-input@6
  • tsx como runtime (NodeNext module resolution)
  • Comunicación HTTP directa al endpoint /mcp

Qué NO incluye (Phase 2)

  • delete_memory — requiere API Key admin
  • Bun compile a binario standalone
  • Selector interactivo de proyecto al arrancar
  • Autenticación por usuario

EntryDetail — vista completa + edición

Muestra el contenido completo con scroll. Permite agregar texto (append_content), tags (add_tags) y cambiar el estado (status).

Análisis automático de candidatos a compactación, preview de los grupos, confirmación interactiva antes de ejecutar. Nunca compacta SUMMARY ni TASK_CONTEXT.

TUI · Uso

Cómo ejecutar la TUI

Después de install-tui (comando global)

memory-tui
memory-tui --project=ecommerce-frontend
memory-tui --url=http://localhost:3100/mcp
memory-tui --url=http://10.0.0.5:3100/mcp --project=mi-proyecto

Desde el repo clonado (desarrollo)

# Directamente con tsx — sin compilar
npx tsx packages/tui/src/index.tsx

# Con flags
npx tsx packages/tui/src/index.tsx --url=http://localhost:3100/mcp --project=mi-proyecto

# Script npm del root
npm run tui

Apuntar al servidor local

# El servidor debe estar en modo HTTP
# .env del servidor:
MCP_TRANSPORT=http
MCP_PORT=3100

# Levantar el servidor
npm run dev --prefix packages/server
# → [team-memory] Streamable HTTP en http://localhost:3100/mcp

# Lanzar la TUI
memory-tui --url=http://localhost:3100/mcp
ℹ️
La TUI verifica /health antes de arrancar. Si el servidor no responde, muestra un error claro en lugar de colgarse.
Interfaz MCP

Las 7 herramientas

save_memory

Persiste + deduplicación automática (exact title + near-duplicate RRF). Soporta force: true. SUMMARY y TASK_CONTEXT exentos del check.

update_memory

append_content suma al final sin destruir. add_tags suma sin reemplazar. Regenera embedding solo si cambia el contenido. No funciona sobre archived.

search_memory

Búsqueda híbrida vectorial + FTS con RRF. SUMMARY excluido por defecto. Registra cada acceso en background sin latencia.

get_context

Contexto al inicio de sesión. SUMMARY y TASK_CONTEXT primero (priority_entries), resto en entries.

list_projects

Lista proyectos activos. Con include_stats: true devuelve breakdown por área, tipo y status.

get_memory_stats

Health completo: overview, top accessed, timeline, autores, candidatos a compactación, riesgo de duplicados. Filtro author y user_id reservado para auth futura.

compact_memory

Compacta entradas antiguas + poco accedidas en SUMMARYs con Ollama. dry_run: true por defecto. SUMMARY y TASK_CONTEXT nunca se compactan.

Calidad del conocimiento

Deduplicación automática en el servidor

Paso A — Exact title match

Normaliza el título (lowercase, trim, colapso de espacios). Sin costo de embedding. Score 1.0. Compara dentro del mismo project + area + type.

Paso B — Near-duplicate (RRF ≥ 0.030)

Genera embedding, corre vectorial + FTS, combina con RRF. Umbral conservador. Mismo project + area + type.

{
  "saved": false,
  "duplicate_detected": true,
  "duplicate": { "id": "uuid", "title": "...", "content_preview": "...", "score": 1.0 },
  "suggestion": "Use update_memory with this entry_id..."
}
✅
El agente evalúa content_preview con contexto conversacional. Score 1.0 → casi siempre update_memory. Score ~0.030 → evaluar y decidir. force: true para insertar igual.

Comportamiento en sesión

Flujo completo del agente

1

Resolver project_slug

Buscar .team-memory.json subiendo hasta .git. Si no tiene slug → flujo interactivo → escribir archivo → recordar commitear.

2

Bootstrap — get_context

Antes de la primera respuesta sustancial. SUMMARY y TASK_CONTEXT llegan primero. Complementar con search_memory según la tarea.

3

Resolver area para cada operación

Cascada: area_map → default_area → heurística → preguntar. Informar la fuente al persistir.

4

Buscar antes de asumir

search_memory antes de responder preguntas técnicas. Si hay ANTI_PATTERN relevante, advertir proactivamente.

5

save_memory → manejar duplicate_detected

El servidor verifica automáticamente. Si devuelve duplicate_detected: true → evaluar content_preview → update o force.

6

Consolidar al cerrar la sesión

Persistir decisiones, fixes, convenciones. SUMMARY si la sesión fue significativa. TASK_CONTEXT para lo que quedó pendiente.

Evaluación

Puntos fuertes y a mejorar

✓ Puntos fuertes

  • On-premise — embeddings y generación 100% locales
  • project_slug explícito y commiteado por repo
  • area_map sistemático — sin inferencias implícitas
  • Deduplicación automática en el servidor
  • Instalación global sin fricción — un comando
  • 5 herramientas de IA soportadas (inc. OpenCode)
  • Credenciales nunca expuestas en modo HTTP
  • TUI para gestión sin pasar por el agente
  • Ciclo de vida completo: tracking + compactación

⚠ A mejorar / explorar

  • Sin autenticación granular (user_id reservado)
  • Sin delete_memory (requiere Fase 2 con API Key)
  • Cursor requiere paso manual (User Rules)
  • Sin versionado de ediciones en update_memory
  • TUI: sin selector interactivo de proyecto al arrancar
  • Dedup solo dentro de project + area + type
  • Distribución TUI manual (sin Bun compile todavía)
